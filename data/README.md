# Участник 4: данные, нормативы и качество

Зона ответственности: эта папка. Backend/frontend ведёт участник 3.

1. Изучить обучающие видео и сформировать категории наблюдаемых событий.
2. Разметить видео: тип события, начало, конец, кадры-доказательства, подходящее правило.
3. Заполнить `rules.json` проверенными и применимыми нормативными источниками РК.
4. Отделить проверочные ролики от данных, на которых команда настраивает модели.
5. Измерять ложные срабатывания, пропуски, точность дробных таймкодов и время обработки.

`rules.json` намеренно пуст: реальные нормативы ещё не исследованы. Не добавляйте
выдуманные статьи и ссылки. Backend проверяет структуру, но не юридическую применимость
источника — её подтверждает участник 4.

Формат корня: `{"schema_version":"1.0","rules":[...]}`.
Каждая запись:

```json
{
  "id": "<устойчивый уникальный идентификатор>",
  "title": "<название правила>",
  "visual_signs": ["<что именно можно увидеть на видео>"],
  "document": "<название проверенного нормативного документа>",
  "section": "<пункт или раздел>",
  "url": "<абсолютная https-ссылка на проверенный источник>",
  "is_demo": false
}
```

Это шаблон, заполнители нельзя использовать в live. Все строки непустые, ID уникальны,
минимум один визуальный признак, URL HTTP(S), без логина/пароля. До 5000 правил и 4 MiB
файла. Схема: `contracts/rules-catalog.schema.json`. `is_demo` можно опустить (false).
Пустой/некорректный каталог блокирует live readiness. Для каждого результата ML2 backend
проверяет `rule_id`, добавляет доверенный источник из каталога и отклоняет его подмену.

**Демонстрационные источники находятся отдельно в `contracts/fixtures/demo-rules.json`.**
Они помечены `is_demo: true`, имеют `demo:` ID и домен `example.invalid`. Это вымысел
для проверки интерфейса. Не переносите их в рабочий каталог: backend их отвергает.
Для воспроизводимого UI-теста используйте `scripts/demo_video.sh`, создающий синтетический
ролик без банковских данных; он не заменяет проверку качества настоящих моделей.

Храните исходные записи в `data/videos/`, локальную разметку — `data/annotations.local.json`.
Оба пути исключены из Git. Не публикуйте банковские видео, кадры и материалы жюри;
не передавайте их внешним облачным AI-сервисам.

Для передачи команде нужны: каталог с подтверждёнными источниками, договорённости
о категориях, независимая проверочная выборка, разметка и список ошибок ML1/ML2.
ML2 пока получает только наблюдения и JPEG, не исходный ролик: оценивайте, хватает ли
этой информации для обоснования события, и фиксируйте случаи недостаточных доказательств.
