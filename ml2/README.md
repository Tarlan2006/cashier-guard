# Участник 2: ML2 — проверка и matching

Ваша зона: `ml2/`. Здесь размещаются код второго этапа и его зависимости.

## Что ожидает backend

- Локальный HTTP-сервис на порту **8002**.
- `POST /match`, JSON: `{ "schema_version": "1.0", "duration_sec": 42.0, "events": [...], "rules": [...] }`.
- `events` — результат ML1, включая кадры-доказательства. `rules` — проверенный каталог участника 4.
- Ответ по `contracts/analysis-result.schema.json`: `verdict` и `violations`.
- Каждый результат: `type`, `timecode_sec`, `description`, 1–3 `evidence_frames`, **rule_id** из переданного каталога.
- Если событий нет: `{ "verdict": "no_violation", "violations": [] }`.

Проверяйте наблюдения по переданным кадрам, объединяйте дубли, отбрасывайте неподтверждённые предположения.
Не придумывайте источники. Backend самостоятельно добавляет объект `rule` по `rule_id` из каталога.
Если для вашего подхода нужны исходный клип или дополнительные кадры, согласуйте расширение контракта с ML1 и backend до реализации.

Адрес задаётся через `ML2_URL`. Все модели работают внутри инфраструктуры команды, без облачных AI API.
Общий бюджет двух этапов и очереди — 280 секунд, по умолчанию каждому HTTP-вызову дан таймаут 120 секунд.
Подготовьте команду запуска, зависимости и сведения о весах для участника 3.
