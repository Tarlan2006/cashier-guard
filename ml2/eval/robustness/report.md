# Устойчивость HTTP ML1 к вариациям открытого видео

Дата: 2026-10-18. Модельная база main `8372756`, код не менялся.
Windows, i5-1240P, CPU, один resident worker, локальные RT-DETR/SigLIP ONNX.
FFmpeg CLI 9.0.2. Проверены только data/open: видео 2 (17.07 с) и 14 (142.53 с).
Закрытые данные и облачные AI API не использовались; кадры не открывались.

Скрипт: [robustness_check.py](../../scripts/robustness_check.py).
Медиа и исходные results.json/report.md лежат во временной папке вне репозитория.
В Git добавлены только код проверки, синтетические тесты и этот текстовый отчёт.

## Условия

Для каждого исходника контроль перекодирован с null-фильтром, затем сделаны
четыре вариации. Везде одинаковые H.264/libx264, yuv420p, CRF 18, preset fast,
threads 2, fps_mode passthrough, без аудио/субтитров/data. FFmpeg применяет
ориентацию при чтении, выходные метаданные поворота очищаются.
Свойства временной шкалы/ошибка таймкодов этим тестом отдельно не проверялись.

| Вариация | Общий для обоих видео FFmpeg-фильтр |
|---|---|
| Контроль | null |
| Отражение | hflip |
| Поворот с кадрированием | rotate=10*PI/180:ow=iw:oh=ih:fillcolor=black,crop=trunc(iw*0.84/2)*2:trunc(ih*0.84/2)*2 |
| Затемнение / контраст | eq=brightness=-0.12:contrast=0.75 |
| Обрезка сверху | crop=trunc(iw/2)*2:trunc(ih*0.85/2)*2:0:trunc(ih*0.15/2)*2 |

Параметры и пороги анализа не менялись, индивидуальных зон/сдвигов таймкодов нет.
Запросы последовательные на 127.0.0.1:8001, без proxy env и redirects.
Модели резидентные; кэш признаков между запросами очищает штатный сервис.
Время ниже — POST вместе с передачей файла/ответом; экспорт FFmpeg и старт
моделей исключены. Это одиночные замеры в рабочей Windows-сессии, не benchmark
изолированного стенда. Проверки/чтение метаданных выполнялись в той же сессии.

## Что можно заключить

- На этих входах сервис не упал, обработка завершилась; partial/timeout не было.
- Включённых правил нет. Нулевые events не измеряют обнаружение нарушений,
  полноту треков или сохранение ролей и опорных предметов.
- ML1 API выдаёт schema_version/events без facts. Для cashier, client,
  counter_machine, safe в результатах скрипта стоит null: «неизвестно», а не «нет».
  Деградация этих признаков по текущему API не оценивается.
- На видео 14 затемнение заняло 102.088 с против 101.836 с у контроля:
  около +0.25%, недостаточно для вывода о замедлении по одному запуску.
  После верхней обрезки время уменьшилось примерно вдвое; считать это улучшением
  качества или объяснять конкретным исчезнувшим объектом без диагностики нельзя.
- Это вариации имеющегося ракурса. Проверка не заменяет другой реальный ракурс,
  размеченную оценку треков/якорей или тестирование на Mac.

## Воспроизведение

Запустите штатный ML1 с локальными весами и одним worker. Из ml2:

```bash
python scripts/robustness_check.py --open-root /path/to/data/open \
  --numbers 2 14 --output /tmp/cashier-guard-robustness \
  --ffmpeg /path/to/ffmpeg
```

Нужна новая output-папка: результаты/медиа не перезаписываются. Скрипт отклоняет
выход внутри checkout, вход вне структуры data/open и внешний HTTP URL.
Новые синтетические тесты проверяют эти границы, отсутствие выдуманных диагностик
при events=[] и сохранение HTTP 504 как ошибки. Общий набор — 191 passed,
27 subtests passed перед первым коммитом аудита; перед каждым следующим коммитом
набор запускается заново. Неизменность production-логики проверена git diff.
