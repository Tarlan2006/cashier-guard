# Windows: сквозная проверка запасного стенда

Дата: 18.10.2026. База: `22e4f66`, `main`. Изменены только новый PowerShell
launcher, инструкция и этот отчёт. Логика анализа, backend, frontend и контракты
не редактировались. Просмотр кадров не выполнялся; использованы только открытые
видео 2 и 14 из `data/open`.

## Окружение и подготовка

Windows 11 Pro 10.0.26200, Windows PowerShell 5.1.26100.9711,
i5-1240P, 8 ГБ RAM, CPU. Python ML: 3.12.10, backend: 3.14.7,
Node: 24.21.0, uv: 0.13.1, FFmpeg/ffprobe: 9.0.2.

- Первый запуск предсказуемо остановился: `Missing uv.exe. Prepare it explicitly:
  winget install --id astral-sh.uv -e (then reopen PowerShell)`
  (`scripts/start-stack.ps1`, `Require-Command`). Сам launcher uv не устанавливал.
- Для проверки uv установлен явно в временную папку вне checkout. Его `bin` и
  каталог уже имевшегося FFmpeg добавлены только в PATH проверочного процесса.
  Системный PATH не изменён. Локальный набор моделей задан через `ML_MODELS_DIR`.
- `uv sync --frozen` выполнен; lockfile не изменён. ML-зависимости проверены по
  установленным версиям и `ml2/requirements.txt`, без импорта тяжёлого PyTorch
  только ради проверки пакетов. Runtime отдельно загрузил обе ONNX-модели.
- Готовой frontend-сборки не было: launcher объявил `npm ci` / `npm run build`,
  обе команды завершились успешно. `npm ci`: 144 пакета, 0 vulnerabilities.
  npm выдал предупреждение об install-script esbuild; сборку оно не заблокировало.
- `download_models.py --source <local-bundle> --verify-only`: все хеши совпали,
  без копирования и сети. Новые модели не скачивались.
- `.env` создан с новым случайным ключом, значение не выводилось. ACL защищён
  от наследования: единственная запись Allow/FullControl — текущий пользователь.
  Проверено также повторное применение ACL. В ходе разработки launcher исправлена
  попытка повторно назначать владельца файла, вызывавшая `SeSecurityPrivilege`;
  конечный вариант меняет только ACL и пропускает уже корректные права.
- `git check-ignore .env work/stack/storage/jobs.sqlite3` подтвердил оба исключения;
  `git ls-files .env 'work/*'` пуст. Медиа, веса, ключи и runtime-логи не включены
  в коммиты. Системная execution policy не менялась: использован процессный Bypass.

## Последовательные задания через backend API

Один запуск `scripts/start-stack.ps1`, реальные ML1 и matching, backend в `live`.
Для каждого видео выполнены multipart `POST /api/v1/analyze` с `X-API-Key` и
опрос `GET /api/v1/jobs/{job_id}` каждые 0,5 с. Видео 14 отправлено только после
терминального ответа по видео 2. Исходные MOV нормализовал сам backend.
Между заданиями сервисы не перезапускались; детекции не подменялись кэшем.

| Открытое видео | Длительность нормализованного видео, с | POST | Job / GET | Verdict | Violations | Время клиента, с | Ошибки |
|---|---:|---:|---|---|---:|---:|---|
| 2 | 17,067 | 202 | done / 200 | no_violation | 0 | 29,457 | Нет |
| 14 | 142,533 | 202 | done / 200 | no_violation | 0 | 90,304 | Нет |

Время клиента измерено от начала загрузки до получения терминального ответа,
включая интервалы опроса. Отдельные времена из ответа backend:

| Видео | Upload | Queue | Preparing / нормализация | Analyzing / ML1 | Matching / ML2 | Total backend, с |
|---|---:|---:|---:|---:|---:|---:|
| 2 | 0,043 | 0,005 | 2,674 | 26,604 | 0,020 | 29,346 |
| 14 | 0,256 | 0,004 | 7,182 | 82,412 | 0,018 | 89,871 |

Это проверка транспорта и выполнения локального анализа. Правила детектора
выключены: `no_violation` означает «наблюдений нет», а не подтверждение соблюдения
кассовой дисциплины. Наличие восьми правил в каталоге не включает их в ML1.

## Негативные проверки и сайт

| Проверка | Фактический результат | Вывод |
|---|---|---|
| Запрос без X-API-Key | HTTP 401, UNAUTHORIZED | Доступ закрыт |
| Неверный X-API-Key | HTTP 401, UNAUTHORIZED | Доступ закрыт |

| Текст под именем invalid.mp4 | POST 202, затем job failed / VIDEO_INVALID | Содержимое проверяется; ошибка не превращается в пустой успешный ответ |

| JS /assets/index-DswCdgBp.js | HTTP 200 | Bundle доступен |

Сообщение для поддельного MP4: «Файл повреждён или его содержимое не является
видео MOV, MP4, AVI, MKV или WEBM.» Источник: `backend/app/media.py:64`, существующая
логика без изменений. HTTP 415 сопоставлен с `UNSUPPORTED_FILE_TYPE` в
`backend/app/main.py:364`. `failed` в этой негативной проверке ожидаем;
оба корректных открытых видео завершились `done`.

Сайт проверен HTTP-запросами и наличием `frontend/dist/index.html`, без снимков
экрана. Ручное взаимодействие с UI и внешний туннель не проверялись.

## Владение процессами и остановка

| Проверка | Результат |
|---|---|
| Повторный launcher при работающем стеке | Exit 1: `Another Windows stack launcher owns this checkout`; исходный ML1 остался healthy |
| Порт 8000 занят отдельным контрольным слушателем | Exit 1: `Port 8000 is occupied. No existing process was stopped.`; слушатель сохранился |
| -Stop во время FFmpeg | До остановки 11 собственных процессов, включая 1 FFmpeg; после — 0 |
| Чужой контрольный процесс при -Stop | Продолжил работать; затем отдельно убран проверочным harness |
| Ctrl+C в изолированном терминале | 10 собственных процессов до, 0 после; терминал вернул код прерывания 1 |
| -Check на конечной версии launcher | Exit 0, готовность и остановка за 7,801 с |
| Порты 8000/8001/8002 после каждой остановки | Нет слушателей; windows-state.json удалён |
| -Stop при отсутствии работающего launcher | Сообщение об отсутствии зарегистрированного стека, без остановки процессов |

Для проверки `-Stop` отправлена дополнительная копия открытого видео 14 и намеренно
прервана во время нормализации. Это отдельный тест остановки, не третья успешная
проверка анализа и не строка таблицы времён. Локальное хранилище/логи остаются в
игнорируемом `work/stack/`. Job Object создаёт процессы приостановленными и включает
их в собственную группу до продолжения выполнения, поэтому venv-redirector,
модельный worker и FFmpeg наследуют принадлежность группе.

## Регрессия и ограничения

| Набор | Результат |
|---|---|
| backend: `.venv/Scripts/python.exe -m pytest -q` | 232 passed, 2 skipped, 1 warning; 28,60 с |
| ml2: `.venv/Scripts/python.exe -m pytest -q tests` | 203 passed, 43 subtests passed; 14,98 с |

Backend пропускает две POSIX-проверки на Windows; предупреждение — существующая
депрекация httpx в Starlette TestClient. FFmpeg/ffprobe были в PATH при pytest.
Тесты выполнены после видеозамеров, чтобы не влиять на время CPU-анализа.

Блокирующих ошибок на двух открытых видео и в конечном launcher не осталось.
PowerShell 7, другие Windows-компьютеры, внешний туннель, работа UI вручную и
распознавание нарушений этим прогоном не проверены. Время — единичный замер на
указанном компьютере, а не гарантия для других записей. Инструкция подготовки,
запуска, туннеля и питания: [STAND_WINDOWS.md](../../../docs/STAND_WINDOWS.md).
