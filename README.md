# Cashier Guard

Основа сервиса для кейса ForteBank: загрузка видео, очередь обработки, API и интерфейс с событиями,
таймкодами и кадрами-доказательствами. **Сейчас работает demo: распознавание нарушений ещё не реализовано.**

## Команда и папки

| Папка | Ответственный | Задача |
|---|---|---|
| `ml1/` | Участник 1 | Анализ видео, наблюдения и кадры |
| `ml2/` | Участник 2 | Проверка наблюдений, matching с правилами |
| `frontend/`, `backend/` | Участник 3 | Сайт, API, очередь и развёртывание |
| `data/` | Участник 4 | Разметка, нормативы, проверка качества |
| `contracts/` | Согласуют все | Форматы обмена между модулями |

## Быстрый запуск

Нужны Node.js 22.12+ (или 24), Python 3.11–3.14, uv и FFmpeg (`ffmpeg` и `ffprobe` в PATH).
На macOS FFmpeg можно установить через `brew install ffmpeg`, uv — по инструкции https://docs.astral.sh/uv/.

Из корня репозитория:

```bash
./scripts/setup.sh
./scripts/dev.sh
```

- Сайт: http://127.0.0.1:5173
- Backend: http://127.0.0.1:8000
- Документация API: http://127.0.0.1:8000/docs
- Уникальный `API_KEY` создаётся в корневом `.env`. Вставьте его в поле «Ключ доступа к API».
- Для остановки обоих процессов нажмите Ctrl+C. Не запускайте второй экземпляр на тех же портах.

Для этого рабочего каталога зависимости и `.env` уже подготовлены при создании основы, поэтому можно сразу использовать `./scripts/dev.sh`.
Новые участники после клонирования начинают с `./scripts/setup.sh`.

## Что работает

- React + TypeScript + Vite, русскоязычный адаптивный интерфейс.
- Выбор/перетаскивание MOV и MP4, предпросмотр, проверка размера и пустого файла.
- FastAPI: `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`, заголовок `X-API-Key`.
- Фоновая очередь, реальные статусы, ошибки, лимит обработки 280 секунд вместе с ожиданием в очереди.
- Извлечение настоящего JPEG из загруженной записи через FFmpeg.
- Два демосценария: тестовое событие и пустой список событий. Пометка demo есть в API и интерфейсе.
- Просмотр доказательств, переход к таймкоду в локальном видео, скачивание JSON.
- HTTP-адаптеры для ML1 и ML2, проверка результата и привязка к источнику из каталога.

Деморежим не определяет, что происходит в видео. Кадр настоящий, а событие — тестовое.
Каталог нормативов пуст, ссылки не выдуманы. Рабочий режим будет готов после подключения моделей и правил.

## Подключение ML после push

1. Участник 1 поднимает `POST /analyze` на 8001 по `ml1/README.md`.
2. Участник 2 поднимает `POST /match` на 8002 по `ml2/README.md`.
3. Участник 4 заполняет проверенные правила в `data/rules.json`.
4. В `.env` задайте `ML1_URL`, `ML2_URL`, `PIPELINE_MODE=live` и перезапустите backend.
5. Проверьте реальный MOV через API и сайт. В интерфейсе демоплашка исчезнет автоматически.

Frontend менять не требуется, если оба модуля соблюдают контракты. Веса моделей выполняются локально
в сервисах команды. Ни видео, ни кадры, ни их описания нельзя отправлять в облачные AI API.
Не используйте звук или распознавание/идентификацию лиц.

## Проверка API

```bash
# Вместо <ключ> используйте API_KEY из .env.
curl -X POST http://127.0.0.1:8000/api/v1/analyze \
  -H 'X-API-Key: <ключ>' \
  -F 'file=@/путь/к/видео.mov'

curl http://127.0.0.1:8000/api/v1/jobs/<job_id> \
  -H 'X-API-Key: <ключ>'
```

## Проверки и сборка

```bash
cd backend
uv run pytest
cd ../frontend
npm run build
```

После сборки backend может отдавать сайт сам на `/`, без Vite:

```bash
cd backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Сначала соберите frontend, потом запускайте backend.

## Границы текущей основы

- Задачи и результаты хранятся в памяти одного процесса. После перезапуска их нужно создать заново.
  Запускайте **один worker Uvicorn**; внутри него два фоновых обработчика и очередь на 16 задач.
- При новой загрузке удаляются завершённые результаты старше часа; максимум 128 результатов.
- Исходник удаляется после обработки или ошибки. На старте удаляются остатки прерванных загрузок.
- Максимальный файл — 100 МБ, длительность — 10 минут; параметры размера и таймаута задаются в `.env`.
- Ключ общий для API, в браузере хранится только в sessionStorage текущей вкладки. Не публикуйте `.env`.
- Веса моделей, реальные нормативы и оценка точности не входят в эту основу.
- Публичный URL ещё не развёрнут. Для жюри нужен ваш сервер, HTTPS и приватный API-ключ;
  `127.0.0.1` доступен только на этом компьютере. Выставляйте сервис через reverse proxy с лимитом
  тела запроса и таймаутами. Для команды позже можно добавить постоянную БД и отдельный worker.
- После загрузки весов и зависимостей обработка не требует интернета; шрифт включён в сборку.
