# Участник 1: ML1 — анализ видео

Зона ответственности: `ml1/`, код, локальные зависимости и модели. Формат согласовывайте
с участниками 2 и 3 через `contracts/README.md`; не меняйте чужие модули без согласования.

Сервис: локальный порт 8001, `POST /analyze`, multipart-поле `file`.
Backend всегда передаёт **нормализованный `video.mp4`**, MIME **`video/mp4`**:
контейнер MP4, одна видеодорожка H.264, пиксельный формат `yuv420p`, без аудио,
субтитров и вложений. Исходная загрузка может быть MOV, MP4, AVI, MKV или WEBM;
их разбор и преобразование выполняет backend. Ответ — `contracts/ml1-response.schema.json`.

Не определяйте формат входа модели по исходному имени пользовательского файла.
Нормализация не задаёт постоянный FPS: используйте временные метки кадров, включая
дробные секунды, вместо предположения `номер кадра / 25` или `/ 30`.
Поворот записи применяется к изображению. Разрешение не уменьшается; для H.264/yuv420p
нечётные размеры могут быть дополнены до чётных без обрезки содержимого.
Нулём времени служит начало исходного контейнера. Его абсолютное смещение убирается,
но промежуток до начала видеодорожки сохраняется: первый PTS не обязательно равен нулю.
Используйте PTS нормализованного MP4 без дополнительного вычитания времени первого кадра.
Это секунды от начала исходного ролика. При наличии начального промежутка `duration_sec`
в результате backend обозначает конец шкалы от нуля, а не только длину видеодорожки.
Конец шкалы определяется видеодорожкой; отдельный аудиохвост исходника в неё не входит.
Не игнорируйте sample aspect ratio при подготовке изображения для модели.
Аудиоанализ по этому входу невозможен.

**Всегда явно возвращайте `schema_version: "1.0"` и `events`, включая пустой список.**
`{}`, пустое тело, `null`, отсутствие полей и неизвестная версия завершают проверку ошибкой,
а не результатом «нарушений нет». Успешный пустой ответ:

```json
{"schema_version": "1.0", "events": []}
```

Наблюдение: уникальный `id`, `start_sec`, `end_sec`, `description`, 1–3 `evidence_frames`
с `timestamp_sec` и `image_base64`. Таймкоды конечные, дробные секунды допустимы.
`0 ≤ start_sec ≤ end_sec ≤ duration_sec`, `start_sec < duration_sec`, кадры `< duration_sec`.
JPEG должен полностью декодироваться: до 8 млн пикселей, 8192 по стороне и 4 млн символов
base64. Всего до 100 наблюдений, HTTP-ответ до 32 MiB.

Описывайте видимые действия. ML2 сопоставляет их с каталогом, но сейчас получает только
ваши наблюдения и кадры, не исходное видео. Доказательств должно хватать для проверки
вывода; потребность в дополнительных клипах обсуждается до изменения контракта.

Адрес: `ML1_URL`. Connect 5 с, write 30 с, read 90 с, весь запрос максимум 120 с;
общий бюджет backend по умолчанию 290 с включает загрузку, очередь, проверку и
преобразование видео, а также оба ML-этапа. У преобразования нет дополнительного бюджета.
Ошибки возвращайте ошибочным HTTP-статусом, не маскируйте их пустым `events`.
Работа — локально, без облачных AI API; код/зависимости/веса должны позволять запуск без
интернета после установки. Для кейса не добавляйте идентификацию лиц.

Перед интеграцией передайте участнику 3 команду запуска, версии зависимостей,
расположение и лицензию весов, требования к CPU/GPU/RAM и измеренное время на видео.
В `demo` ваш сервис не вызывается. `live` требует оба сервиса и проверенный каталог.


## Локальные эксперименты ML1

Исходники нашей части опубликованы в `ml1/`. Точки входа, состав моделей,
зависимости, реальные ограничения и следующие шаги — [INTEGRATION.md](INTEGRATION.md).
Подробный HANDOFF с локальными путями и примерами передаётся команде отдельно.
Новые scene/SAM-каналы пока не подключены автоматически к HTTP-сервису `ml2/`.

- `scene_mvp/engine.py` — калиброванные геометрические и временные наблюдения.
- `run_person_tracks_trial.py`, `prepare_scene_mvp.py`, `run_scene_mvp.py` —
  локальный проход, подготовка профиля камеры и сборка кандидатов.
- `run_sam2_object_trial.py`, `run_sam2_transfer_trial.py` — сопровождение
  указанного человеком предмета; тип и роли не распознаются SAM автоматически.
- `predict_object_event.py` — небольшая обученная модель сумки/документов.
- `export_scene_handoff.py` — ML1-compatible JSON и 1–3 исходных JPEG.
- `outputs/forte_cash_workflows.json` — общая политика цепочек, без предсказаний
  и индивидуальной разметки видео. Это правила прототипа, не юридический вердикт.

Дополнительные инструкции: [TEAM_HANDOFF.txt](TEAM_HANDOFF.txt),
[OBJECT_EVENT_MODEL.txt](OBJECT_EVENT_MODEL.txt),
[OBJECT_CROP_TRAINING.txt](OBJECT_CROP_TRAINING.txt).

Видео, кадры, human-review JSON, веса, среды и полная история опытов остаются
локальными. Для воспроизведения нужно отдельно предоставить нужные assets и
подтверждённый camera profile. Автоматическая цепочка удостоверение → деньги →
машина → сейф пока не прошла достаточную проверку. Пустые кандидаты не доказывают
полноту проверки или отсутствие всех нарушений.

Быстрые синтетические проверки без inference:

```bash
PYTHONDONTWRITEBYTECODE=1 python -B -m unittest discover -s ml1/scene_mvp -t ml1 -p 'test_*.py' -q
```
