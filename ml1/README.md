# Участник 1: ML1 — анализ видео

Ваша зона: `ml1/`. Можно разместить свой Python-проект, зависимости и локальные модели.
Не меняйте frontend/backend без согласования формата в `contracts/README.md`.

## Что ожидает backend

- Локальный HTTP-сервис на порту **8001**.
- `POST /analyze`, multipart-поле **file** с видео.
- Ответ JSON по `contracts/ml1-response.schema.json`.
- `schema_version: "1.0"`, `events`: список наблюдаемых событий (может быть пустым).
- Событие: `id`, `start_sec`, `end_sec`, `description`, `evidence_frames` (1–3 JPEG в base64 с `timestamp_sec`).

Описывайте видимые действия, не придумывайте нормативную оценку. ML2 выполняет проверку и matching.
JPEG должен быть настоящим кадром, а таймкод — соответствовать исходному видео.
Анализируйте последовательность кадров локально, без облачных API, звука и идентификации лиц.

## Перед интеграцией

Сообщите участнику 3 команду запуска, требования к железу, расположение весов и время обработки.
Адрес настраивается через `ML1_URL` в корневом `.env`.
Общий бюджет очереди и двух ML-этапов — 280 секунд; оставляйте запас для передачи результата жюри.
В `demo`-режиме ваш сервис не вызывается. Переключение на `live` выполняется после готовности обоих модулей и каталога правил.
