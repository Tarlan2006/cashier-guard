ForteBank: следующий этап работы с датасетом

forte_annotations_draft.json — черновик для команды, а не готовая разметка нарушений и не ответ модели.
В нём 40 уникальных видеорядов, 42 исходные записи организаторов и 23 записи возможных событий.
Описания видео, типы и нормативные ссылки в событиях пока пусты. Заполнять их локально.

Учтены временные уточнения:
X-4 и X-47: общий видеоряд, отдельные записи на 57 и 68 секундах.
X-13: отдельные записи на 47 и 50 секундах.
X-15: 15 секунд.
X-38: одна запись с основной отметкой 33 секунды и дополнительной 52 секунды.
Исходные строки организаторов сохранены внутри source_annotations.

1. Участник по датасету и правилам
Просмотреть каждую запись локально. Для события заполнить observation_local и type_local.
Выбрать правило только после проверки его условий и исключений.
rule_references — список объектов с полями document, url, paragraph; при наличии добавить rule_id.
Спорные случаи оставлять insufficient_data. Неподтвердившиеся гипотезы — dismissed.
reviewed_candidate означает проверенный человеком кандидат для оценки системы, а не доказанное правонарушение.
Не устанавливать этот статус, пока нет основания, проверенных исключений и реальных кадров.
При пропущенном действии поставить is_omission=true, указать контекст и проверить видимость всей операции.
Отдельно просмотреть 19 уникальных видеорядов с исходной отрицательной меткой.
full_video_review_status=reviewed означает, что просмотрен весь видеоряд.

2. Участник по AI
Разработать локальное получение событий и реальных кадров из загруженного видео.
Использовать черновик для проверки поведения, после заполнения человеком.
Не определять результат по имени файла, исходной метке, хешу или заготовленным таймкодам.
Все копии одного sha256 должны находиться в одной выборке. split заполняется один раз для группы:
development, validation или holdout. Разделение на выборки ещё не выполнено.
Формат evidence_frames_local: список из 1–3 объектов с timestamp_sec и path.
path — относительный путь к реальному JPEG, например evidence/X-4-E01/frame_01.jpg.
Кадры и описания обрабатываются и остаются локально.

3. Участник по backend
Принять формат событий от AI, преобразовать реальные JPEG в base64 и вернуть API по кейсу.
POST /api/v1/analyze: multipart file, авторизация X-API-Key, ответ job_id.
GET /api/v1/jobs/{job_id}: processing/done/failed; при done — verdict и violations.
Публичный verdict: violation или no_violation. Внутренние статусы разметки не заменяют контракт API.
Не использовать этот черновик как готовые ответы на загруженные ролики.

4. Участник по frontend
Показать загрузку, состояние анализа и список событий с таймкодами, реальными кадрами и нормативными основаниями.
В одном видео может быть несколько событий. Несколько кадров и отметок одного события не увеличивают число событий.

Проверка структуры без установки библиотек (из папки outputs):
python3 validate_forte_annotations.py forte_annotations_draft.json

Проверка перед передачей проверенной разметки:
python3 validate_forte_annotations.py forte_annotations_draft.json --require-reviewed

Второй запуск сейчас должен сообщить о незавершённой ручной проверке.
Проверяющий скрипт не выводит описания роликов, не читает видео, не оценивает законы и не проверяет существование файлов кадров.
Нормативный каталог forte_rules_kz.json — начальная версия; он не покрывает все возможные события.
