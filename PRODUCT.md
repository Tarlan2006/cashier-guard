# Cashier Guard

Cashier Guard помогает человеку проверять записи банковских кассовых операций. Пользователь
выбирает MOV, MP4, AVI, MKV или WEBM, сохраняет ключ в настройках, запускает проверку и изучает события, время, кадры и
источники правил. Окончательное решение принимает человек. Облачные AI-сервисы,
аудиоанализ и идентификация лиц не входят в продукт.

## Текущая готовность

Работает основа frontend/backend. Backend сохраняет demo-режим для тестов; отдельного
сценария демопроверки в пользовательском интерфейсе нет. ML1 и ML2 подключаются как локальные
HTTP-сервисы; рабочий каталог нормативов и разметку предоставляет участник по данным.
Точность распознавания и выполнение реальных моделей на целевом железе пока не подтверждены.
ML2 сейчас получает наблюдения и JPEG-кадры от ML1, а не исходный ролик.

Проверки `/health` и `/ready` сохраняются для загрузки и обработки ошибок, но индикатора
доступности backend в хедере нет. Новая проверка доступна только когда оба ответа имеют
режим `live`, а `/ready` возвращает `ready: true`. При отсутствии готового реального анализа
показано «Анализ видео пока недоступен»; выбор и локальный просмотр файла остаются доступны.
Доступный TCP-порт модели не подтверждает загрузку весов или корректность анализа.
Ошибка, недоступность и некорректный ответ ML означают отсутствие подтверждённого результата,
а не вердикт «нарушений нет». Публичный сервер и HTTPS ещё должны быть предоставлены
и проверены; наличие конфигурации Docker/Caddy не означает развёрнутый сервис.

## Одна проверка от загрузки до результата

Основное действие — «Загрузить видео». После выбора файла появляется «Проверить видео»,
использующая существующий обработчик реального анализа; без готового сервиса действие
недоступно. Основная поверхность содержит видео слева и результат справа; на телефоне
панели идут последовательно. Верхняя навигация открывает пять разделов: «Проверка видео»,
«Нормативы РК», «API», «Архитектура», «Настройки». Переключение сохраняет выбранный файл,
текущую задачу и сохранённый ключ. В «Настройках» раздел «Подключение API» содержит поле
с показом/скрытием, кнопки «Сохранить» и «Удалить ключ». Ввод становится ключом запросов
только после сохранения; удаление очищает существующую запись ключа в sessionStorage.
На странице видео поля ключа нет. При выбранном файле без ключа рядом с запуском показано
«Настройте подключение для проверки видео» со ссылкой «Открыть настройки».
Раздел нормативов показывает ссылки текущего live-результата, исключая помеченные
демонстрационные источники;
раздел API — фактический JSON текущей задачи, без ключа доступа; архитектура описывает
реализованный путь обработки. Пустые состояния не заменяются примерными результатами.
После ошибки авторизации ссылка ведёт в настройки для исправления ключа;
текущую проверку можно продолжить с сохранённым значением. Временные сетевые ошибки имеют ограниченные повторы; окончательная
ошибка освобождает интерфейс для новой проверки или запроса статуса сохранённой задачи.
Повторная отправка POST автоматически не выполняется.

Восстанавливается только текущая проверка этой вкладки: браузер сохраняет `job_id` и ключ
в `sessionStorage`, backend — статус и результат в SQLite. После обновления страницы
пользователь снова видит задачу. Локальный File/Object URL не сохраняется: для просмотра
ролика нужно повторно выбрать файл с теми же именем и размером. Это не запускает анализ
повторно и не доказывает совпадение содержимого файлов. Кадры результата доступны отдельно.

Завершённые результаты по умолчанию хранятся один час; срок показан в интерфейсе, результат
можно скачать как JSON. Фоновая очистка запускается раз в минуту. Исходный файл удаляется
после завершения или ошибки. При перезапуске backend завершённый результат остаётся в SQLite,
а прерванная проверка получает понятную ошибку `SERVER_RESTARTED`. Общий серверный бюджет
по умолчанию 290 секунд включает загрузку, очередь и ML; по истечении срока формируется
ошибка. Личных кабинетов, разграничения результатов по пользователям и полной истории нет.

## Работа с доказательствами

Список событий синхронизирован с отметками на шкале видео; время отображается до миллисекунд.
Кнопки времени и клавиатурная шкала позволяют перейти к событию. Действие «Посмотреть ±3 секунды»
проигрывает контекст в пределах начала и конца ролика, затем останавливается. Эта возможность
требует локального файла и поддерживаемого браузером кодека.

Каждое событие содержит 1–3 JPEG. Кадр открывается в модальном просмотре с режимами «Уместить»
и «Увеличить 2×» и прокруткой деталей. При открытии фокус переходит на кнопку закрытия,
Tab/Shift+Tab остаются внутри просмотра. Escape закрывает просмотр, фокус возвращается к
открывшей его кнопке. Доступны видимый клавиатурный фокус, текстовые статусы и reduced motion.

## Достоверность результата и визуальная система

Кнопка запуска демопроверки, выбор тестового сценария и связанные элементы удалены.
Интерфейс не подменяет недоступный анализ заранее заданными событиями. Восстановленные
записи с `mode: demo` остаются явно обозначенными: события и уровни заданы тестовым
сценарием, ML не анализировал содержимое видео. Их вымышленные источники не включаются
в раздел нормативов и не выдаются за нормативы РК.

Визуальная система следует полному JSX-референсу пользователя: светлый slate-фон,
белые скруглённые панели, розовые основные действия, тёмная видеоповерхность и верхняя
навигация вместо зелёного бокового меню. Название продукта остаётся Cashier Guard.
Красный, янтарный и зелёный сохраняют отдельное значение уровней оценки с текстовыми
подписями. Не выдумывать нормативы, точность, статистику или подтверждение готовности моделей.
